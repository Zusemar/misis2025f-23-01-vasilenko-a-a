# Сегментация сечений грецкого ореха

Проект разделяет одноканальные КТ-реконструкции 501 × 501 на три класса:
**0 — воздух/фон, 1 — скорлупа и видимые перегородки, 2 — ядро**.
Сегментация реализована на C++20 и OpenCV. Python используется для оценки,
подбора параметров на настроечной части и подготовки иллюстраций.

Данные: [12 TIFF преподавателя](https://github.com/dvpsun/misis2025f-23-00-polevoi-d-v/tree/main/data/walnut01).
Опорная статья: [Der Sarkissian et al., 2019](https://doi.org/10.1038/s41597-019-0235-y).
Все основные материалы проекта находятся внутри этой папки.

## Результат текущего этапа

Реализованы два способа сегментации и три варианта предобработки.
По настроечной части выбран метод по областям без сглаживания.
Guided filter реализован и проверен в сравнении, но на данной выборке
не дал преимущества, достаточного для его включения в основной вариант.

| Вариант | IoU скорлупы | IoU ядра | Средний IoU этих классов |
|---|---:|---:|---:|
| Пороги без фильтра | 58,82% | 73,79% | 66,30% |
| Области без фильтра | 94,99% | 96,70% | **95,84%** |
| Области + guided filter | 94,84% | 96,68% | 95,76% |

Значения получены на 8 контрольных сечениях относительно полуавтоматической
разметки v0.1. Они характеризуют согласие с этой разметкой, а не независимую
экспертную точность или переносимость на другие орехи.

## Сборка и запуск

Нужны CMake ≥ 3.20, компилятор C++20 и OpenCV 4 с `core`, `imgproc`, `imgcodecs`.
Модуль `ximgproc` не требуется: guided filter реализован через `boxFilter`.
Ниже команды выполняются из корня репозитория.

```sh
cmake -S walnut01 -B walnut01/build -DCMAKE_BUILD_TYPE=Release
cmake --build walnut01/build --parallel
ctest --test-dir walnut01/build --output-on-failure

# Одна картинка или папка TIFF; разметка для этого запуска не нужна.
walnut01/build/walnut_segment walnut01/data/images walnut01/results/my_run \
  --config walnut01/configs/recommended.json

# Ветка обработки с фильтром, сохраняющим границы.
walnut01/build/walnut_segment walnut01/data/images walnut01/results/my_guided \
  --config walnut01/configs/guided_regions.json
```

На Windows следует учесть расположение `.exe` в каталоге выбранной конфигурации
сборки. Проверенная среда: macOS, AppleClang 17, OpenCV 4.13.0; сборка на
других системах в рамках этого этапа не выполнялась.

Программа принимает **float32 TIFF без RGB и без NaN/отрицательных значений**.
Неподходящий тип отвергается с объяснением, а не молча преобразуется в другую
шкалу. Параметры яркости рассчитаны на шкалу этой учебной выборки, а радиусы
заданы в пикселях. Для другого разрешения и другой шкалы требуется проверка
параметров.

Результат запуска:

- `masks/` — числовые PNG 0/1/2;
- `filtered/` — обработанные float32 TIFF в исходной шкале;
- `intermediates/` — реальные промежуточные маски тканей, центральных областей
  и автоматических маркеров, сохранённые из C++;
- `parameters.json` — фактические параметры и версия OpenCV;
- `diagnostics.csv` — пороги и время вычисления без чтения/записи изображений;
- `regions.csv` — признаки автоматически найденных центральных областей.

Большие промежуточные float32 TIFF не включены в Git; они воспроизводятся
командой запуска. Изображения этапов и числовые маски сохранены в репозитории.

## Воспроизведение экспериментов и изображений

```sh
python -m pip install -r walnut01/tools/requirements.txt
python -m unittest discover -s walnut01/tests -p 'test_*.py' -v

# Полный подбор только на development, затем оценка control.
python walnut01/tools/run_experiments.py

# Повторный запуск с уже зафиксированными параметрами, без подбора.
python walnut01/tools/run_experiments.py --reuse-selection

# К каждому из 12 сечений: этапы обработки и сравнение с картой ошибок.
python walnut01/tools/visualize_results.py

```

`results/gallery.html` открывается в браузере и показывает все 12 сечений.
Для каждого есть раскрывающийся блок с промежуточными результатами.
Первые две панели фильтрации — сравниваемые ветки обработки; они не выданы
за обязательные последовательные шаги основного варианта без фильтра.

## Данные и оценка

Разделение до подбора параметров записано в `configs/protocol.json`:

- настройка: `0130`, `1230`, `1430`, `2130`;
- контроль: `0230`, `0330`, `0430`, `1130`, `1330`, `2230`, `2330`, `2430`.

Проверено 108 конфигураций. Каждый вариант настраивался по среднему IoU
скорлупы и ядра на development. Помимо сравнения настроенных вариантов
сделана отдельная абляция: те же параметры сегментации, изменяется только
фильтр. Сводка находится в `results/summary.csv`, подробности — в
`per_image_metrics.csv` и `metrics.json`.

При первом техническом прогоне отдельный тест обнаружил, что класс ядра
мог распространяться вдоль тонкой перегородки. Исправление сделано по
искусственному примеру. Параметры после раскрытия контрольных результатов
не перенастраивались: итоговые измерения используют ту же `selection.json`.
Исходный технический прогон сохранён в `results/technical_trial_before_septum_fix/`.
Поэтому контроль следует понимать как повторную проверку фиксированных
параметров после исправления реализации, а не как новый независимый тест.

Отсутствующий и в разметке, и в предсказании класс даёт `null` в JSON и
пустое значение в CSV, а не искусственные 100%. Основные IoU/Dice вычисляются
из суммарной матрицы ошибок. F1 границ — среднее по сечениям с определённой
метрикой, допуск — 1 пиксель в окрестности 3 × 3. Дополнительно рассчитаны
метрики вне полосы неопределённости разметки; основные цифры в таблице
выше относятся ко **всем пикселям**, без такого исключения.

Разметка [описана отдельно](annotations/README.md). Координаты её точек,
огибающие, исправляющие штрихи, маски и имена сечений в алгоритм C++ не входят.
Однако сама разметка готовилась с помощью яркостных операций. Это ограничивает
независимость проверки методов с похожими признаками и требует последующей
экспертной проверки перед более сильными выводами.

Подробное описание этапа, ошибок и выводов: [техническая записка](reports/stage_02.md).
